# 0〜1,280世代の学習規則を使うFPGA実験

専用worktree・ブランチ `fpga/learned-pattern`。通常の先読み並行化版
`24171f4` から派生しています。回路変更は `src/cart/city_accelerator_nowater.v`
のみです。学習・評価コードと結果をこのディレクトリに追加しています。
既存の `.sof` には本実験は含まれません。

## 何を学習したか／低ビット化

モデル種別は **有限期間のセル別定数規則＋予測を見送る選択器** です。
浮動小数点のニューラルネットや、その重みのINT8/INT4量子化は未実装です。
GPU上の整数データから、各セルが最後に変化した世代を抽出し、ある世代以降に
定数0・1・100を返せるセルと通常計算に戻すセルを選びます。
この試作は対象軌跡への過学習を許し、汎化性能は要求していません。

FPGAにはセルごとの規則を2 bitで格納します。

| ビット | 処理 |
| --- | --- |
| 00 | 既存の正確な近傍計算 |
| 01 | 次世代値0 |
| 10 | 次世代値1 |
| 11 | 次世代値100 |

初期配置の照合用7 bitと組み合わせて1セル9 bit、1,024ワードの同期ROMです。
モデルの重み、浮動小数点演算、乗算器を実行時に持たず、M9K **1個の追加**を狙います。
元の8-bitグリッドや既存の整数演算はそのまま扱います。

学習対象は、変更していない `linux_city.c` がseed 6502から生成した0〜1,280世代です。
学習器は候補となる開始世代を走査し、行ごとの動的計画法で予測／通常計算を選びます。
通常計算への復帰時には近傍キャッシュを補充する必要があるため、補充のコストまで
含めて0→1,280世代の合計クロック数を最小にする候補を選択します。

今回の選択は、**入力世代86〜1,279において648/960セルを定数予測**するものです。
内訳は0が50セル、1が582セル、100が16セルです。残り312セルは従来の規則で計算します。
定数予測セルは2クロック、キャッシュが利用できる通常計算セルは7クロックです。
予測セルを挟んだ後や行頭では、通常計算用の25セルを27クロックで補充します。

全1,281盤面をそのまま保存すると1,229,760 bytesになります。
今回は小さな選択規則に絞りました。全セルをモデル単体で出力する実装ではありません。

## 精度と適用条件

量子化・整数化した**最終ROMのビット列**をCの全盤面に照合しています。
`learned.py verify` は学習側のPyTorchを使わず、この照合を再実行し、
RTLに埋め込まれたROMと世代範囲がモデルJSONと一致することも確認します。

- モデルが予測する773,712出力は773,712個すべて一致（受理した予測の精度100%）。
- 0→1,280世代の全1,228,800出力に対するモデルの担当率は62.964844%。
  残り455,088出力は既存の正確な計算です。
- 統合RTLは0〜1,300世代の全960セルを毎世代Cと比較し、すべて一致しました。
- 訓練範囲への適合試験であり、未知の配置・世代に対するモデルの正答率を示しません。

最初のSTARTでは、グリッド全960 **bytes** をROM中の初期値と照合します。
グリッド側の最上位bitも比較するため、7-bitへの切り捨てやCRCの衝突で認定しません。
初期値が一致してから、CPUによる盤面書き込みが一度もなく、かつ対象世代範囲内の
場合だけ予測を有効にします。CPU書き込みは同じ値でも認定を無効化します。
学習上の「最後の変化」を永久の収束とはみなさず、1,280→1,281以降は通常計算です。
リセット後は認定を取り直します。STARTとソフトリセットの同時指定時は予測を使いません。

START時の認定・世代範囲判定を同期して計算側へ渡し、DONEまで保持します。
DONE通知時には初期値照合結果が十分長く安定した状態でCPU側に渡ります。
最終書き込み、ダブルバッファ、BUSY中のCPUアクセス遮断は従来の仕組みを使います。

## 測定結果

2026-09-06。詳細とソースSHA-256は `learned_results.json`、
学習結果・各候補のコスト・ROMの全ワードは `learned_model.json` に保存しています。

| 計算クロック数（10 MHz、CPU 100 MHz） | 通常版24171f4 | 学習規則版 |
| --- | ---: | ---: |
| 0→1（初期値照合込み） | 6,400 | 7,361 |
| 1→2〜85→86 | 6,400 | 6,400 |
| 86→87〜1,279→1,280 | 6,400 | 4,133 |
| 1,280→1,281以降 | 6,400 | 6,400 |
| 0→1,280の合計 | 8,192,000 | 5,486,163 |
| 合計の10 MHz換算 | 0.8192000秒 | 0.5486163秒 |

合計で **1.493倍**、予測が有効な世代では **1.549倍**の計算速度です。
初期値が不一致の場合も最初の照合には961クロック追加されます。
MMIO STARTからBUSY解除までの測定で、実際のNES描画・CRC・CPU命令による
ポーリング時間を含むアプリ全体の速度ではありません。
CPU半周期7 nsでは1世代当たりそれぞれ1クロック増えました。

### MAX10リソース

| アクセラレータ単体、同一評価フロー | 通常版24171f4 | 学習規則版 | 差分 |
| --- | ---: | ---: | ---: |
| Yosys組合せセル | 1,256 | 1,354 | +98 |
| FF | 514 | 543 | +29 |
| DSP | 0 | 0 | 0 |
| グリッドRAM | 2,048×8 bit | 2,048×8 bit | 0 |
| モデル・照合ROM | 0 | 1,024×9 bit | 9,216 bit |
| 想定M9K数 | 2 | 3 | +1 |

**M9K数は構成からの見積もりです。** MAX10は1ブロックの1,024×9構成をサポートします
（[Altera公式メモリ構成](https://docs.altera.com/r/docs/683431/current/max-10-embedded-memory-user-guide/memory-configurations-for-dual-port-modes)）。
使用したYosysの実験的MAX10 backendでは、初期値付きROMが`INIT`パラメータの
変換エラーになりました。独立2クロック書き込みRAMもこのbackendでは未変換です。
`learned_resources.py` は両メモリを `$mem_v2` として保持し、同じロジック変換を
通常版にも適用して比較しています。初期値を削除して合成を通す処理はしていません。
このフローは旧 `resources.py` と異なり、旧記録の1,223セルとは直接比較しません。

LUT/FFはLE内で共有されるため、単純和をLE使用数とは扱えません。
単体のガードは組合せセル1,600以下、FF650以下、DSPなし、RAM/ROM形状の一致です。
Quartus、実機ともこの環境にはなく、NES全体のFitter、ROM/RAM推論、TimeQuest、
実画面は未検証です。対象`10M08SAE144C8GES`への最終的な収容保証はしていません。

## 検証と再実行

共通環境はC/C++コンパイラ、Python 3、Verilator、Icarus、Yosysです。
データ生成・整数モデル照合・RTL試験にPython外部パッケージは不要です。

```sh
export PATH=/tmp/mics-fpga-tools/oss-cad-suite/bin:$PATH

# C由来の1,281盤面を生成／最終ROM表現を再検証
python3 Nescity_FPGA/eval/learned.py generate
python3 Nescity_FPGA/eval/learned.py verify

# 355配置、2,078世代（標準配置は1,300世代）、算術全数、4値の通常経路
python3 Nescity_FPGA/eval/run.py --steps 1300 --extra-checks
python3 Nescity_FPGA/eval/run.py --steps 1300 --cpu-half 7

# 初期値の先頭・中間・末尾の上位bit違い、別世代の盤面からの開始、
# 学習経路中のCPU編集・同値書き戻し、リセット、START+リセット同時指定、8時点での計算中断
# 各クロック設定で18ケース／2,716世代
python3 Nescity_FPGA/eval/check_learned_guards.py
python3 Nescity_FPGA/eval/check_learned_guards.py --cpu-half 7

# 学習経路も含め90世代の4値シミュレーション（上記run.pyのvectors.binを使用）
iverilog -g2012 -s four_state_tb -o Nescity_FPGA/eval/.build/learned-four-state.vvp \
  Nescity_FPGA/eval/four_state_tb.sv Nescity_FPGA/src/cart/city_accelerator_nowater.v
vvp Nescity_FPGA/eval/.build/learned-four-state.vvp \
  +vectors=Nescity_FPGA/eval/.build/vectors.bin +steps=90

# RAM/ROMを保持する本実験専用のリソース比較
python3 Nescity_FPGA/eval/learned_resources.py
```

標準配置はREADMEの全6点のCRCも一致しています。一般試験の各設定には18時点の
計算中リセット復帰を含みます。学習専用試験では、リセット後に再び86世代を越えても
認定が誤って残らないこと、CPUの異なるクロック位相でも同じ結果になることを確認しました。
Verilatorの幅警告は抑制せず、元からの独立2クロックRAMのMULTIDRIVEN警告のみ抑制しています。

### 学習の再現

今回の学習は許可された`192.168.9.100`のRTX 3090、PyTorch `2.13.0+cu130`で実行しました。
既存サービスを操作せず、`vllm/vllm-openai:v0.27.1`イメージの独立した一時コンテナを使用しました。
コンテナはネットワークなし、CPU 2、メモリ2 GiB、非root、PyTorchのGPUメモリ上限3%で実行し、
終了時に削除しました。学習中の実行時依存はPyTorchとNumPyです。

```sh
# GPU環境にtraining.binとスクリプトをコピーして実行
python3 train_patterns.py training.bin trained.json
# GPUがないPyTorch環境では --device cpu でも同じ整数規則を生成できる

# 得られたJSONをローカルへ戻してから、検証付きで埋め込み直す
python3 Nescity_FPGA/eval/learned.py export --model /path/to/trained.json
```

モデルを変更した場合は `learned_model.json` も置き換え、全RTL検証とリソース評価を
再実行してください。`learned_results.json` は今回の測定記録で、自動で最新化されません。
