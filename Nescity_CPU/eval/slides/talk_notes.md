# 発表メモ

本編19枚＋付録2枚、約18分を想定（要リハーサル）。測定対象は1756db3、記録日は2026年9月6日。今回の資料更新では性能測定を再実行していない。付録は質問に応じて使用する。数値の詳細と再現条件は `../RESULTS.md` と `../README.md` を参照。

1. **導入**：古い6502、2 KiBの内部RAMという条件で、同じ計算結果を維持して付属初期配置の1280世代でCPUサイクル比70.615倍を記録した。CPUシミュレーションであり、実機性能は未測定。
2. **結果**：1280世代の合計サイクルを比較して70.61451095倍（表示は70.615倍）。平均値は四捨五入して表示。配布版合計54,222,785,215、最新版767,870,293、平均42,361,551対599,899、削減率98.58%。測定区間はsim_step先頭からRTSまでで、呼出元JSR・CRC・NMIを除く世代更新だけで、描画や待ち時間を含む実機FPSとは区別する。
3. **問題の構造**：32×30の盤面を同時更新する。端は反対側につながる。重みの合計65は平均計算にも使う。水不足の自動計算は配布版で無効だが、外から値を設定する試験は行った。
4. **制約**：配布済みコードで変更したのはCPU側のnescity.cだけ。評価環境は別に追加。ゼロページも2 KiBの内数であり、無料の追加メモリではない。
5. **通常版**：各出力セルが25近傍を読み直す。6502には汎用の乗除算命令がなく、生成される補助関数の処理も大きい。
6. **開発段階**：5.216倍、11.668倍、51.805倍、56.989倍、65.068倍、70.615倍と改善した。棒は通常版に対する累積倍率。各版は複数の変更を含むので、棒の差を単独の工夫の効果とは呼ばない。
7. **列の再利用**：重みを縦方向と横方向に分解する。縦5セルの結果を5列分保持して窓をずらす。800→180は32セルをすべて集計する基本方式の論理的な集計対象数で、一様列判定なども含めた実際のメモリアクセス数ではない。最新版では固定セル区間の列集計を先送りするため、上記は実装全体の一律のアクセス数でもない。草原の影響力は重みに依存しない例外なので、人口と影響力を同じ式だけで処理しない。
8. **除算の表引き**：平均はfloor(n/65)。影響力の差分は元の式 `(force-20)/20` に対応し、負数はゼロ方向に丸める。バイアスを加えた添字なら `(index-150)/20`。過密度損失は正の範囲で `(avg-55)/3*4` に対応する。有限の全入力を検査できることが強み。生成コードの汎用乗除算・剰余呼出し検査は主要15関数で、初期化・数字描画は対象外。
9. **6502への適合**：影響力の加算バイアスは全近傍で130となり、変換表で取り除ける。列集計を非負の8ビット範囲に収め、人口和だけ下位・上位を分離する。固定添字の命令列では、キャリーが立たない値の範囲も確認している。
10. **省略の条件**：経験的に変わらなかったケースを省くのではなく、取り得る最大値から結果が確定する場合に早期終了する。山の条件は付録で説明する。
11. **住宅数再利用と先送り**：07b8126で縦5セルの住宅数32列＋端の複製4 B、計36 Bを保持。書き戻し前に抜ける旧行を引き、入る旧行を足す。海だけの行でも更新し、下端では保存した旧先頭行を使う。固定セル区間で列集計を先送りし、距離5未満なら再利用、5以上なら5列を再構成。列集計の初期化は世代開始時だけ。
12. **ループとレジスタ**：1756db3で世代ループを6502化し、行ポインタと3行循環管理を直接処理。32 B専用コピーを8 Bずつ展開する。横位置をYに保持し、計算対象到着時だけ距離を計算。人口和上位バイトをXに保持し、繰り上がった時だけ増やす。人口和は16ビットを維持。採用系列651,037→624,641→610,968→599,899は複数変更の逐次比較で、各試作を1280世代照合した記録。旧先頭2行の保存、2行遅れの書き戻し、最後の2行の処理順序は維持。
13. **資源**：PRGは配布版から7,547 B（約7.37 KiB）増えて20,702 Bとなるが32 KiB以内。ゼロページは229 B（残り27 B）。DATA+BSSとCスタックの最小間隔60 Bは今回の実行時監視の結果で、任意の将来変更への保証ではない。3行＋旧2行という更新方式は通常版から維持した。
14. **評価環境**：同一固定cc65・8bitworkshop、フラグ -t nes -Oirs -Cl -g で3版を再ビルドする。配布済みROMとのバイナリ一致は保証しない。ホスト上のC実行時間で6502性能を推定するのではなく、cc65で作ったROMをsim65のCPUコアで走らせる。ホスト参照モデルは正解の盤面を作るために使う。簡易PPUは起動・再描画経路を確認するもので完全なNESエミュレータではない。
15. **正しさ**：初期状態を含む1281盤面の各960セルをbaseline・07b8126・1756db3で比較。追加279配置（最新版のみ）は一様配置、乱数、周期境界、山の閾値などを含み、それぞれ2世代を検査した。CRCだけではなく全セルで照合する。
16. **盤面依存**：初期5世代は直前版5,309,703から最新版4,987,782サイクルへ、6.45%高速化。平均997,556、配布版比41.686倍。旧57倍版の初期平均1,012,976より速く、07b8126で生じた初期区間の退行を解消した。測定した1280世代では各世代とも直前版より速く1.064〜1.099倍。ただし任意の盤面に対する保証ではない。
17. **開発方法**：通常版をタグで保存し、依存バージョンを固定。短い比較試験で誤りを見つけ、生成アセンブリとサイクル内訳で次の改善箇所を決めた。最終候補は長い比較と資源検査を通してからGitに記録した。
18. **残る処理**：最新の自己サイクルは列集計51.60%、セル更新21.24%、行ループ14.50%、住宅数の行送り5.46%、固定長コピー2.20%、その他5.00%。呼出し先を含まない。割合の増加だけで絶対サイクルの悪化を判断しない。直前版比1.085倍＝速度向上8.52%、サイクル削減7.85%。旧資料eb9c478比1.239倍＝23.91%高速化、19.30%削減。63e14f3から追加2倍という目標には約1.363倍で未達。最新の分類ID差分更新案651,929は比較対象651,037より遅く不採用。旧3セル＋2セル分類表789,451対743,334はeb9c478開発時の別の不採用記録で、最新版の測定値に混ぜない。
19. **結び**：計算の再利用、正確な表引き、6502向けの実装を組み合わせた。今後はFPGA実機での表示と実時間を確認する。LE・FF・BRAMやタイミング収束は今回測っていない。
20. **付録A**：中心が山、住宅が0か1の場合に影響力の上限を求める。海の個数で場合分けしても局所補正込みで最大−2。平均補正が最大+1でも成長せず、下限1への制限で次も1になる。元のルール定数が変われば証明を更新する。
21. **付録B**：実行コマンドと各コミットを示す。依存の初回取得にはネットワークが必要。`git diff baseline 1756db3 -- Nescity_CPU/8bitworkshop/nescity.c` で配布版からの変更を確認できる。


## 補足する検証条件と資源量

- 掲載版eb9c478比はPRG+316 B、ZP+39 B、DATA+BSS−2 B、静的RAM合計+37 B。直前07b8126比はPRG+19 B、ZP+2 B、DATA+BSS−2 Bで静的RAM合計不変。比較起点を区別する。
- 最新版DATA+BSSは1,208 B、ZPとの合計1,437 B。静的データ末尾$07B8からRAM上限まで72 B。Cスタック観測最下点$07F4との余裕60 Bとは別の値。RAM全体の安全性を静的データの合計だけで説明しない。
- ハードウェアSP最小値は旧版・直前版$ED、最新版$EE。CHRは2,192 B／8,192 B、iNESファイルは40,976 B。盤面960 B、次世代3行96 B、旧先頭2行64 Bを維持する。
- 追加配置191から279への内訳は、対象間隔0〜31×海・山の64配置、海だけの行4配置、非一様縦5セル10種類×周期境界2位置の20配置。255/256、767/768付近の繰り上がりを検査する。
- 既存の一様101値、乱数、周期境界、住宅0/1/2件×海0/1/3/4/12/22セルの18組、水不足0/1/12/127/128/129/134/135/254/255を維持。全6501入力と326・101要素の表の全数検査も維持する。短縮試験は5世代＋223配置であり、完全評価と区別する。
- CRCは初期37C2、5世代D764、1280世代1FC3のまま。起動から5世代の盤面・CRC・ネームテーブルが一致。起動試験NMI回数はeb9c478で358、07b8126で366、最新版356。実機FPSには換算しない。意図的なスタック衝突試験も期待どおり失敗した。
- 従来の6フレーム待ち・再描画頻度を維持。70.615倍はアプリ全体の速度倍率ではない。簡易PPUの起動試験は完全なNESエミュレーションや実機表示確認ではない。実機動作、表示・処理速度、QuartusのLE/FF/BRAM使用率、タイミング収束は未評価。回路・.sofは変更していない。
- 全セル比較・境界試験の結果を全盤面の網羅証明とは呼ばない。スタック余裕は観測値であり、将来変更後の安全性の保証ではない。大会規則の確認は同梱資料に限定する。
